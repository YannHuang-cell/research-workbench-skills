# Entry Modes

Use this file to decide how to start from the available artifact and how fine-grained the next unit should be.

## Full Paper Or PDF

- Collect title, authors, venue or year, and section map first.
- Inspect visible links for supplement, code, or data early.
- Start with `Skim` unless the user already wants a focused section or deep read.

## Abstract, Introduction, Or Conclusion Only

- Start with `Skim` or a light `Knowledge-Point Deep Read`.
- Mark all paper-wide judgments as provisional.
- Say what remains unknown because the full paper is not visible.

## Specific Paragraph Or Section

- Stay scoped to the excerpt.
- Prefer `Knowledge-Point Deep Read` or `Review Mode` depending on the excerpt.
- Briefly say what role the excerpt likely plays in the paper.

## Figure, Table, Or Formula Only

- Start with `Figure/Table/Formula Mode`.
- Explain what claim the item seems to support before details.
- Avoid pretending to know the full paper if it is not visible.

## Title Or Citation Only

- Do not start deep tutoring.
- Either do a lightweight triage or request inspectable content.

## Unit Size

Default to the smallest meaningful knowledge point, not one sentence at a time.

Use larger units when:
- adjacent sentences serve the same role,
- the user wants speed,
- or the text is simple and repetitive.

Use smaller units when:
- one sentence is the bottleneck,
- notation or OCR is noisy,
- or the user is confused.

## Mid-Session Switching

- Start broad, then narrow.
- Move from `Skim` to `Knowledge-Point Deep Read` once the user commits to the paper.
- Move from prose reading to `Method Breakdown` when the user asks about mechanism.
- Move to `Obsidian Output` only after enough understanding is already built.
