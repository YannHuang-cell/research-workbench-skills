# Checkpoint Patterns

Use this file when deciding how to test understanding without slowing the session down.

## Default Cadence

- Ask one short checkpoint question after each teaching unit.
- Skip the question only when the user clearly wants a fast pass and no confusion is visible.
- Revisit one earlier key idea after every few units rather than only testing the most recent part.

## Good Default Question Types

### Recall
- `作者这里真正要解决的问题是什么?`
- `这一段最核心的结论是什么?`

### Explain Why
- `作者为什么要这样设计?`
- `如果不做这一步，会有什么后果?`

### Contrast
- `这个做法和前一个 baseline 的关键区别是什么?`
- `这里的设定和前面的假设有什么不同?`

### Transfer
- `如果数据更少，这个方法最可能先坏在哪里?`
- `如果换任务，这个结论还站得住吗?`

## Adapting To The User

- Correct but vague: ask one narrower follow-up.
- Partly correct: keep the correct part, repair the missing part, then ask one targeted follow-up.
- Wrong or `没懂`: reteach the same unit at a lower abstraction level.
- Wants speed: ask fewer questions before reducing explanation quality.

## Anti-Pattern

- Do not ask two obvious questions when one real question is enough.
- Do not turn the session into an exam.
- Do not keep questioning after the user explicitly chooses to continue quickly.
