# Research KB Builder

Build a second brain that is usable under real attention limits.

- Prefer low-friction structure over decorative complexity.
- Use note types and properties to reduce classification anxiety.
- Treat Obsidian as an active research system, not a static archive.
- Keep Zotero as the literature fact layer and Obsidian as the thinking layer.

## Core Note Types

- Paper note
- Concept note
- Method note
- Code note
- Project note
- Idea note
- Weekly review note

Use `references/vault-structure.md` for the object model.

## Default Workflow

1. Identify the source artifact:
   - paper understanding
   - code understanding
   - project update
   - new idea
2. Choose the note type.
3. Fill the smallest useful template.
4. Add links to related notes.
5. Keep only the metadata that improves retrieval.

## Design Rules

- Use a small number of folders.
- Use stable note types.
- Use properties for structure, not excessive tags.
- Prefer explicit links between projects, papers, methods, and ideas.
- Keep templates short enough that the user can actually fill them.

## ADHD/OCD Guardrails

- Avoid over-customized dashboards at the start.
- Avoid too many note categories.
- Avoid forcing every note to be complete before it becomes useful.
- Prefer small consistent layouts over perfect formatting.
- Separate `capture now` from `refine later`.

## Output

Produce Markdown that can be written directly into Obsidian.

- keep headings stable
- keep metadata light
- keep related links explicit
- keep the writing compressed and reusable

Use `references/note-templates.md` for starter templates.

## Boundaries

- Do not turn the vault into a dumping ground.
- Do not overbuild plugin-dependent structure before the user has stable habits.
- Do not auto-write Zotero tags.
- Do not create note formats that are too heavy to maintain daily.
